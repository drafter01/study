# 26. 전시 게임 프로토타입 v0.2 「모임 설계자」

> 파일: game/moim.html (브라우저에서 바로 실행) / 아티팩트: https://claude.ai/artifact/4xBE5Z2iPMn4CGckNbQ35E (비공개)
> 상태: 프레임워크 v0.2 전에 만든 탐색용 프로토타입. 프레임워크가 나오면 카드·게이지·사건을 그 구조에 맞춰 바꾼다 (게임을 만들며 프레임워크의 애매한 곳을 찾는 용도로도 사용)

## v0.2 변경 (연구자 피드백: 텍스트가 많고 클릭이 많음, 1~3분 안에)
- 매 모임 카드 선택 → **스킬 포인트 분배** 방식(RPG 레벨업)으로 변경
- 모임 8번은 자동으로 진행되고, **동심원 시각화**로 지켜봄
- 사건(딜레마)은 빼고, 레벨 업 때 **진단 한 줄**로 대체 (UX 조사의 역할)

## 한 판의 흐름 (1~2분, 클릭 약 10~15번)
1. 모임 고르기 (1번)
2. 스킬 포인트 8점 나누기 (약 8번)
3. 모임 4번 자동 진행 (약 8초)
4. 레벨 업: 경험치 → 포인트 2~6점, 진단 한 줄 보고 추가 분배 (약 3~5번)
5. 모임 4번 자동 진행 → 리포트
6. 전시용: 리포트 60초, 그 외 2분 동안 입력이 없으면 처음 화면으로

## 시각화
- 동심원: 바깥부터 처음 온 사람 → 다시 온 사람 → 자리 잡은 사람 → 함께 이끄는 사람, 가운데 운영자
- 점 = 사람, **선 = 사람 사이의 관계**. 선이 있는 사람이 다시 올 확률이 크게 높음 → "사람과 사람 사이를 설계한다"를 눈으로 보여줌
- 떠나는 사람은 바깥으로 흩어지며 사라짐
- 가운데 고리 = 운영자 에너지 (스킬이 많을수록 줄고, 함께 이끄는 사람이 나눠 듦)

## 스킬 5개와 긴장
| 스킬 | 효과 | 부작용(긴장) | 연구 근거 |
|---|---|---|---|
| 열기 | 새 사람 유입 | 맞이할 수 있는 인원보다 많이 오면 첫 연결 확률 하락, 높으면 자리 잡은 사람 일부 이탈 | 낮은 문턱 ↔ 의도된 마찰, 트레바리 대중화 |
| 맞이 | 처음 온 사람이 누군가와 이어짐, 한 번에 챙길 수 있는 인원 증가 | - | 온보딩, Lu 외 2017 |
| 리듬 | 다시 오기·자리 잡기 | 맞이 없이 높으면 처음 온 사람에게 부담 | 자유 ↔ 리듬 |
| 연결 | 구성원끼리 관계 형성 | 연결 높고 열기 낮으면 새 사람이 끼기 어려움 | 소속감 ↔ 배타성 |
| 자리 | 함께 이끄는 사람 | - | Reader-to-Leader, Lang 동심원 |
- 모든 스킬은 운영자 에너지를 씀 → 다 올릴 수 없음 (지속 운영, 번아웃)
- 자리 잡은 사람이 친구를 데려옴 → 관계가 관계를 부름

## 밸런스 확인 (자동 플레이 각 6판, 잠정)
| 전략 | 결과 |
|---|---|
| 유입 위주 (열기 5) | 6판 모두 북적이지만 머무르지 않는 모임 |
| 닫힌 관계 (연결 4, 열기 0) | 6판 모두 끈끈하지만 닫힌 모임 |
| 관계 위주 (맞이·연결·리듬·자리) | 스스로 굴러가는 모임 4, 조용히 자라는 모임 1, 아직 뿌리내리지 못한 모임 1 |
| 균형 (열기 2 포함) | 스스로 굴러가는 모임 2, 조용히 자라는 모임 2, 북적이지만 머무르지 않는 모임 2 |

## 연구와의 연결
- 리포트의 공동체 의식 4요소는 McMillan & Chavis(1986). 값은 스킬과 결과에서 계산한 은유적 표시
- 리포트의 "다녀간 사람 → 남은 관계"는 허영 지표 대신 행동 신호를 보라는 Lang·07번 평가 도구의 메시지

## 주의
- 수치는 게임 디자인을 위해 정한 값이며 연구 결과가 아님 → 화면에 명시
- 스킬 이름(열기·맞이·리듬·연결·자리)은 임시. 프레임워크 v0.1의 요소 이름이 정해지면 맞춤
