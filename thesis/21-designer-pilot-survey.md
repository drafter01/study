# 21. 디자이너 대상 예비 설문 (RQ3 적합성, 약 5분)

> 목적: "커뮤니티 과제는 UX 과업과 닮았다"는 연구자의 실무 관찰을, 답을 유도하지 않는 방식으로 확인
> 성격: 연구자가 아는 디자이너 커뮤니티에 올리는 편의 표본 → 논문에서는 "예비 조사"로 보고, 일반화하지 않음

## v2 변경 (답변률)
- 필수 서술형은 Q4 하나만 남김("한두 줄, 키워드만" 안내). Q5는 균형 잡힌 보기의 객관식, Q8은 선택 응답
- 한계: 객관식 보기는 떠올리기(회상)가 아니라 고르기(재인)라 유도 가능성이 조금 생김 → 보기를 디자인·운영·관계·규칙·그냥 두기로 균형 있게 구성하고 순서를 섞어 완화

## 유도를 줄이는 원칙
1. 가설을 드러내지 않는다 ("UX 과업과 닮았다", "온보딩" 같은 말을 쓰지 않음)
2. 떠올리게 한 뒤 평가하게 한다 (자유 응답 상황 질문 → 평가 문항 순서)
3. 비교 대상을 섞는다 (UX와 닮은 일 + 운영·행정 + 관계·거버넌스)
4. 디자인과의 연결은 응답자가 고르게 한다 ("디자인 경험이 도움이 되나요?" 대신 자신감 + 그 출처)

## 게시글
- 제목: 커뮤니티·모임 운영에 관한 5분 설문 부탁드려요 (졸업논문 예비 조사)
- 안내: 졸업논문 예비 조사로, 커뮤니티나 모임을 운영하는 상황을 어떻게 바라보는지 묻는 짧은 설문입니다. 정답은 없고 익명으로 진행되며, 개인을 알아볼 수 있는 정보는 수집하지 않습니다. 응답은 연구 목적으로만 사용합니다. 언제든 중단하셔도 됩니다. ☐ 확인했고 참여에 동의합니다

## 문항
### 1. 기본 정보
- Q1 현재 직무: UX/UI 디자이너 / 프로덕트 디자이너 / UX 리서처 / 그 외 디자인 직무 / 기타
- Q2 실무 경력: 1년 미만 / 1~3년 / 3~7년 / 7년 이상
- Q3 커뮤니티·모임 운영 경험(복수): 없음 / 일회성 모임 주최 / 정기 모임 운영 / 업무로 커뮤니티 운영
### 2. 상황 질문 (자유 응답)
- Q4 동네에서 매주 모이는 15명 규모의 독서모임 운영을 맡게 되었습니다. 최근 석 달 동안 매번 3분의 1 정도가 말없이 빠집니다. 어떻게 하시겠어요? 생각나는 순서대로 적어주세요.
- Q5 (v2: 객관식으로 변경, 답변률 고려) 모임에 처음 온 사람이 다음 모임에 다시 오는 경우가 적습니다. 가장 먼저 해볼 일 하나를 골라주세요. (보기 순서 섞기)
  - 다시 오지 않은 사람들에게 이유를 물어본다 [조사]
  - 첫 모임의 진행 방식을 바꿔본다 [경험 설계]
  - 모임 소개와 신청·안내 과정을 다시 살펴본다 [접점 점검]
  - 처음 온 사람에게 개별 연락해 다시 와달라고 한다 [운영]
  - 기존 멤버에게 새로 온 사람을 챙겨달라고 부탁한다 [관계]
  - 뒤풀이나 친목 자리를 만든다 [관계]
  - 출석 규칙이나 보증금을 만든다 [규칙]
  - 원래 그런 것이라 크게 신경 쓰지 않는다 [그냥 두기]
  - 기타
  - [ ]안 분류는 응답자에게 비공개. 앞 세 개 = 디자인 방법
### 3. 평가 질문
- Q6 아래 일을 맡는다면 어느 정도 자신 있게 해낼 수 있을 것 같나요? (1 전혀 자신 없다 ~ 5 매우 자신 있다 / 잘 모르겠다) — 구글 폼 격자형, 항목 순서 섞기
  1. 처음 온 사람이 어색하지 않도록 첫 모임 진행 방식 정하기
  2. 다시 오지 않는 사람들의 이유 알아내기
  3. 모임 소개글과 신청 과정 만들기
  4. 모임이 끝난 뒤 의견을 받아 다음 모임에 반영하기
  5. 모임 방식을 조금씩 바꿔보고 반응 비교하기
  6. 회비를 걷고 정산하기
  7. 모임 장소를 찾고 예약하기
  8. 멤버 사이의 말다툼 중재하기
  9. 분위기를 해치는 멤버에게 주의 주기
  10. 오래된 멤버와 새 멤버가 잘 섞이게 하기
  11. 운영을 도와줄 사람을 찾고 일을 나누기
- Q7 자신 있다고 답한 일은 주로 어떤 경험 덕분인가요?(복수): 디자인 업무 경험 / 커뮤니티·모임 경험 / 디자인이 아닌 다른 업무 경험 / 일상생활 경험 / 기타
- Q8 가장 자신 없는 일과 그 이유 (v2: 선택 응답)
### 4. 마지막 (선택, 앞 문항에 영향을 주지 않도록 맨 끝)
- Q9 기회가 있다면 직접 커뮤니티나 모임을 만들어볼 생각이 있나요? (1~5) / 망설여진다면 가장 큰 이유는?

## 분석 계획 (응답 수집 전에 고정)
- Q4 자유 응답 분류 기준 (Q5는 객관식 분포로 분석: 디자인 방법 3개 보기를 고른 비율)
  - 디자인 방법: 조사·인터뷰·설문, 흐름이나 접점 점검, 가설과 실험, 피드백 반영과 반복
  - 운영·관계 방법: 개별 연락, 규칙·벌칙, 친목·뒤풀이, 리더·운영진 지정
  - 기타
  → 묻지 않았는데 디자인 방법을 먼저 꺼내는 비율 = 적합성의 근거
- Q6 묶음 (응답자에게 비공개, 10번 대응표 기준)
  - UX 과업과 닮은 일: 1~5 / 운영·행정: 6~7 / 관계·거버넌스: 8~11
  - 묶음별 평균 비교. 1~5 > 8~11이면 A 유형(통함)과 B·C 유형(확장·전환 필요)의 근거. 다르게 나와도 그대로 보고
- Q7: 자신감의 출처로 "디자인 업무 경험"을 고른 비율
- Q3 운영 경험 유무에 따라 Q6 비교 (경험 효과와 디자인 효과 구분)

## 확인 사항
- 커뮤니티 관리자에게 게시 허락
- 학교 IRB 필요 여부
- 목표 응답 수: 30명 이상이면 묶음별 비교를 서술적으로 보고 가능 (통계 검정은 하지 않음)

## 결과별 해석 시나리오 (응답 수집 전에 고정)
| 결과 | 해석 | 논문에서 바뀌는 것 |
|---|---|---|
| ①예상대로: 1~5 높음, 8~11 낮음, 자유 응답에 디자인 방법이 자주 등장 | 닮은 부분(A)과 확장·전환이 필요한 부분(B·C)이 디자이너 인식에서도 구분됨 | 5장 근거로 그대로 사용 |
| ②모두 높음: 관계·거버넌스(8~11)도 자신 있음 | 디자이너가 관계 과제도 자신 있어 함. 단 자신감 ≠ 능력. 선행연구(오지현 외, 09번 사례)는 이 영역의 어려움을 보여줌 → **자신감과 현장의 어려움 사이의 간극** | 프레임워크가 "보이지 않는 함정"(배제, 신구 갈등, 번아웃)을 짚어주는 역할 강조. 운영 경험 유무로 비교해 경험 없는 집단의 과신 여부 확인 |
| ③모두 낮음: 1~5도 자신 없음 | 구조적으로는 닮았지만(대응표) 디자이너는 자기 역량이 옮겨갈 수 있다고 **인식하지 못함** | "닮았다"를 "잠재적 적합성"으로 낮춤. 인식의 간극 자체가 시야 확장과 프레임워크의 필요성 근거. 단, 자유 응답에도 디자인 방법이 없으면 적합성 전제를 약하게 서술 |
| ④자유 응답에 디자인 방법이 거의 없고 운영·친목 방법이 대부분 | 디자이너도 커뮤니티 앞에서는 일상적 직관으로 접근함 → 역량이 자동으로 옮겨가지 않음 | "디자이너가 자연스럽게 잘한다" 주장 배제. 프레임워크를 "디자인 방법을 커뮤니티로 옮겨 쓰게 돕는 다리"로 위치 |
| ⑤Q9 의향 낮음 | "디자이너가 커뮤니티를 만든다"는 수요가 아직 크지 않음 | 연구를 현재 수요의 반영이 아니라 **제안**으로 서술. 장벽 응답을 프레임워크 요구사항으로 사용 |
| ⑥응답 30명 미만 | 수치 비교는 의미 약함 | 자유 응답 위주로 질적 보고 |

## 원칙
- 어떤 결과든 그대로 보고하고, 해석은 위 표를 따른다 (결과를 본 뒤 유리하게 바꾸지 않음)
- 이 설문은 근거의 한 축일 뿐, 중심 주장은 공고 분석·문헌·전문가 검토와 함께 판단
- 주장 수정이 필요한 경우: 자신감이 낮고(③) + 자유 응답에 디자인 방법이 없고(④) + 전문가 검토에서도 활용 가능성이 낮게 나오면 → "닮았다"는 전제를 크게 수정
- 일찍 실시해 결과에 따라 조정할 시간을 확보
