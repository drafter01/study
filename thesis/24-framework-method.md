# 24. 프레임워크 도출 방법 (6장 방법 절의 뼈대)

> 원칙: 기존 프레임워크(Community Canvas, Community Weaving)에서 출발하지 않는다. 연구 근거에서 아래로부터 도출한 뒤 비교한다. 23번 초안은 비교용 참고안으로 둔다.

## 0. 설계 조건 정하기 (거의 완료)
| 항목 | 내용 |
|---|---|
| 목적 | 취향·활동 기반 혼합형 소규모 커뮤니티의 구성원 경험을 설계하고 점검 |
| 사용자 | 바깥 겹: 누구나(운영자·비영리 활동가·모임장) / 안쪽 겹: 디자이너 |
| 수준 | 원칙과 핵심 질문 (전술 X) |
| 형태 | 가볍게, 혼자서도 쓸 수 있게 |
| 판단 기준 | 공동체 의식(McMillan & Chavis) + 행동 신호 |

## 1. 근거 모으기 (자료 이미 확보)
- 2차 자료 17건(05), 원문 노트 7편(sources/notes), 운영자 사례(09), Lang 강연(04), 대응표(10)
- 추후 추가: 회원 설문(14), 디자이너 예비 설문(21) 결과

## 2. 발견 추출 (근거 표)
- 분석 단위: "구성원 경험에 영향을 주는 요인에 대한 발견" 한 문장
- 열: ID / 출처 / 발견 / 어떤 순간(시점) / 무엇이(대상) / 어떤 결과 / 근거 유형(실증·사례·이론) / 연구자 해석 여부
- 산출물: data/evidence_findings.csv

## 3. 묶기 (어피니티 다이어그램)
- 미리 정한 범주 없이 비슷한 발견끼리 묶어 주제를 만든다 (개방 코딩)
- 두 축을 따로 확인: 시점(언제), 대상(무엇을)
- 묶는 과정과 판단 근거를 기록(감사 추적)

## 4. 원칙 만들기
- 포함 기준: 근거 2개 이상, 그중 1개 이상은 실증 또는 이론
- 원칙 형식: 원칙 / 핵심 질문 / 근거 / 설계 긴장 / 디지털 제품과 다른 점 / 신호
- 근거가 1개뿐인 주제는 "후보"로 남기고 설문·전문가 검토로 확인

## 5. 구조 정하기
- 3·4단계 결과를 보고 결정: 요소형 / 단계형 / 단계 × 요소
- 기준: 근거에 맞는가, 혼자 쓰기 쉬운가, 빈칸 없이 채워지는가

## 6. 기존 프레임워크와 비교
- 수렴: 비슷하게 나온 부분 → 타당성 근거
- 차이: 새로 나온 부분 → 기여 (단계별 긴장, UX 번역, 사용자-사용자 관점, 신호, 국내 근거)

## 7. 두 겹으로 쓰기
- 바깥 겹: 쉬운 말의 질문
- 안쪽 겹: 10번 대응표의 A(그대로)·B(확장)·C(관점 전환)로 UX 방법과 연결

## 8. 검증하고 고치기
- 사례 적용: 취향 커뮤니티 / 디자이너가 만든 커뮤니티 / 비영리 커뮤니티 (각 사례에 질문을 적용해 보고 빈칸·어색한 곳 기록)
- 서면 전문가 검토(15): 디자이너 + 운영자
- 설문 결과 반영 → v1.0

## 버전 계획
- v0.1: 1~5단계 (근거 기반 원칙과 구조)
- v0.2: 6~7단계 (비교, 두 겹)
- v1.0: 8단계 (적용과 검토 반영)
