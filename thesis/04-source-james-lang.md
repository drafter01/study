# 04. 자료 분석: James Lang, "If you can design an app, you can design a community"

- 형식: Rosenfeld Media 온라인 강연 (Rosenverse Live, 5월, 2025년으로 추정). 실무자 발표이고 동료 심사를 거친 연구가 아님
- 연사: 전 YouTube UX 리서치 디렉터. 자원봉사 단체 Together by Design 소속(연구자, 디자이너, 예술가, 교육자 15명)

## 핵심 주장
1. UX 역량으로 커뮤니티를 설계할 수 있다
2. 커뮤니티는 설계할 수 있는 대상이다. 다만 기계처럼 만드는 것이 아니라 정원을 가꾸듯 다뤄야 한다
3. 커뮤니티 설계는 서비스디자인의 하위 분야인데, UX는 약 80억 달러 규모의 커뮤니티 산업에 거의 기여하지 못하고 있다

## 논문에 쓸 근거
| 내용 | 논문 연결 |
|---|---|
| 커뮤니티 정의: 소속감과 동일시를 일으키는 것 | 공동체 의식 이론과 일치 |
| 운영자들은 디자인이라고 부르지 않아도 디자인 프로세스(니즈 발견, 리서치, 아이디어, 프로토타입, 공동 창작)를 따른다 | 명제 C |
| 디자인 프로세스 대응: 발견(여정지도) → 아이디어(캔버스, 최소 기능 커뮤니티) → 프로토타입(beacon action) → 테스트(재참석률, 40% 미만이면 가치 제안 재검토) → 확산 | 명제 C, 방법 매핑 |
| 마찰을 줄이는 대신 일부러 만든다: 안전과 진지한 참여를 위해 | RQ3, UX가 바꿔야 할 관점 |
| 규모 확장 대신 전파: 던바의 수, 지부, 하위 모임, parkrun | 소규모 커뮤니티 트렌드 |
| 기계가 아니라 정원 가꾸기 | 디자이너 역할의 한계와 태도 |
| 윤리: 기만적 설계가 다른 분야보다 더 큰 정서적 피해를 줌. 착취적 커뮤니티 비판 | RQ3, 윤리 원칙 |
| 설계 원칙: 함께하기(같은 활동을 동시에), 첫 추종자, 안전한 공유, 마법의 원, 하나의 공유된 목적 | 프레임워크 원칙 후보 |
| 패턴 라이브러리: 함께 먹기(potluck), 걷기 + 이야기(Story Walk, 8~10명이 한계) | 사례 적용 장 |
| 측정: 가입자 수는 허영 지표. 신규 회원 환영, 재참석, 함께 보내는 시간, 나눔(호혜성) 같은 행동 신호 | 판단 기준 |
| 초기 실패 원인: 피상적인 목적 합의, 첫 모임에 아무도 안 오는 상황, 역할 불명확, 결핍 관점 → 자산 관점 | 시작 단계 |
| 생애주기: 시작한 사람과 유지하는 사람은 다르다. 동심원(핵심 2~3명 → 적극 참여 12명 내외 → 외곽), 승계 계획, 창립자 번아웃 | 주도 단계 |
