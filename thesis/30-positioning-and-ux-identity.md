# 30. 기존 프레임워크 대비 강점과 UX 정체성 (잠정, 프레임워크 도출 전)

## 강점이 될 수 있는 지점 (우월성이 아니라 목적과 만드는 방식의 차이)
| | Community Canvas | Community Weaving | Microsolidarity | 우리 |
|---|---|---|---|---|
| 바탕 | 실무자 경험 | 실무자 경험 | 실천 공동체 경험 | 연구 근거 (근거 표 발견 번호로 추적) |
| 보는 방식 | 정체성·경험·구조 | 은유(불·그물·리듬·원·나선) | 집단 크기 | 시간에 따른 구성원 여정 (처음 옴 → 다시 옴 → 자리 잡음 → 이끎 → 떠남) |
| 어려움 | 질문 목록 | 원칙 | 실천법 | 설계 긴장 (얻는 것과 잃는 것) |
| 확인 방법 | 거의 없음 | 거의 없음 | 거의 없음 | 관계 신호 + 공동체 의식 척도 |
| 맥락 | 해외 | 해외 | 해외 | 국내 2030, 온·오프라인 혼합 소규모 |
- 가장 강한 차별점: ① 일회성 만남 → 다시 오는 관계로의 전환에 집중 (함연수 외 서울연구원) ② 원칙마다 근거와 측정 신호
- 인정할 약점: 기존 프레임워크는 오래 쓰였고 범위가 넓음. 우리는 검증 전이고 범위가 좁음
- 논문 문장: "기존 프레임워크가 실무자의 지혜를 정리한 것이라면, 본 프레임워크는 그 지혜와 수렴하는지 확인하면서 근거와 측정을 더한 설계 도구다"

## UX 디자이너가 만든 도구로 보이게 하는 형식
| UX 도구 | 커뮤니티 버전 |
|---|---|
| 사용성 휴리스틱 (Nielsen) | 커뮤니티 휴리스틱: 모임을 점검하는 원칙 + 핵심 질문 ← 1순위 후보 |
| 고객 여정 지도 | 구성원 여정 지도: 단계별 순간, 이탈 지점 |
| 서비스 블루프린트 | 커뮤니티 블루프린트: 무대(구성원이 보는 것)와 뒤편(운영자의 일, 소진 지점) |
| HEART 지표 | 관계 신호: 다시 온 비율, 신규 환영, 나눔, 공동체 의식 |
| A/B 테스트·반복 | 작은 실험: 한 번에 하나씩 바꿔 보기 |
| 인터랙티브 프로토타입 | Community Design Simulator (전시 게임) |
- 형식만 빌리고 원칙의 내용은 근거 표에서 아래로부터 도출 (27번 방법과 충돌하지 않음)
- 5단계(구조 정하기)에서 "휴리스틱 + 여정 지도 + 신호" 조합을 후보로 검토
