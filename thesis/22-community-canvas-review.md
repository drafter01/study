# 22. 기존 프레임워크 비교 ①: Community Canvas

## 서지
Pfortmüller, F., Luchsinger, N., & Mombartz, S. (2017). *The Community Canvas Guidebook* (Version 1.0, May 2017). https://community-canvas.org/ (CC BY-NC-SA 4.0)
- 읽은 범위: 가이드북 PDF 텍스트 중 서론, 세 섹션 개요, Member Selection, Member Transition, Rituals, Organization 부분 / 17개 주제와 핵심 질문은 Commons Library 요약과 가이드북으로 대조
- 프로젝트는 종료됨(사이트와 가이드북은 공개 유지). 후속 Community Canvas 2.0은 나오지 않은 것으로 보임. 후속 성격의 Community Weaving 프로젝트(Lang 강연에서 언급)는 Notion 페이지가 열리지 않아 확인 못 함

## 정의
"a community is a type of organization that brings people together and makes them feel like they belong" (p.3) — 소속감 중심 정의로 Lang, McMillan & Chavis와 같은 방향

## 구조: 3개 섹션, 17개 주제 (각 주제는 핵심 질문으로 구성)
| 섹션 | 질문 | 주제 |
|---|---|---|
| 정체성 Identity | 우리는 누구이고 무엇을 믿는가 | 목적, 구성원 정체성, 가치, 성공의 정의, 브랜드 |
| 경험 Experience | 커뮤니티에서 무슨 일이 일어나고 구성원에게 어떤 가치를 주는가 | 구성원 선발(입구), 구성원 전환(출구), 공유 경험, 의례와 전통, 콘텐츠, 규칙, 역할 |
| 구조 Structure | 장기적인 안정성은 무엇에서 오는가 | 조직, 거버넌스, 재정, 채널과 플랫폼, 데이터 관리 |
- 정체성이 시각적으로도 가운데에 있고 다른 모든 것에 영향 (p.5)
- 최소 기능 커뮤니티(Minimum Viable Community) 템플릿: 핵심 질문 9개, 정체성과 경험 섹션만 다룸. 구조 섹션은 성숙한 단계에서 중요 (UNaLAB 툴킷)

## 우리 연구와 직접 연결되는 내용
- **Member Selection**: 개방형은 포용적이지만 "더 모호"해지고, 폐쇄형은 "엘리트주의"의 인상을 줄 수 있으며 투명한 선발이 이를 일부 상쇄 (p.24) → 설계 긴장 "낮은 문턱 ↔ 의도된 마찰", "소속감 ↔ 배타성"의 실무 근거
- **온보딩**: 환영받고 안전하다는 느낌, 핵심 가치와 규칙 소개, 기대되는 헌신 명확화, 분명한 첫 몇 걸음, 그룹 안의 첫 연결 돕기. "가능한 한 개인적일수록" 잘 작동 (p.25)
- **Member Transition(출구)**: 대부분의 커뮤니티는 시작은 고민하지만 끝은 계획하지 않음. 경험에 끝을 두면 핵심 기간의 활동과 리텐션이 높아짐. 비활성 회원을 정의하고 다시 참여시키거나 내보내는 절차, 동문 커뮤니티 (p.27)
- **Rituals**: 의례는 구성원 경험의 단계(시작, 성장, 끝)를 표시하는 통과의례 (p.33) → 단계 축과 연결
- **Organization**: 열정의 주기가 식으면 자원이 줄어듦 → 성숙한 커뮤니티는 꼭 지켜야 할 "최소 핵심 활동"을 정해둠 (p.46) → 주도·지속 단계, 운영자 번아웃

## 우리 프레임워크와의 비교
| 기준 | Community Canvas | 우리 프레임워크(안) |
|---|---|---|
| 조직 방식 | **무엇을** 다루나 (주제별 분류) | **언제**(단계) × **무엇을**(설계 대상) |
| 시간 축 | 입구와 출구만 있고 중간 단계는 없음 (의례에서 단계 언급) | 시작 → 진입 → 재방문 → 정착 → 주도(→ 전환) |
| 긴장·딜레마 | 성찰 글 안에 암묵적으로 (개방 vs 폐쇄 등) | 단계마다 설계 긴장을 명시 |
| 근거 | 저자들의 15년 경험 + 실무자 의견 (학술 근거 없음) | 이론·질적 연구·설문으로 추적 가능한 근거 |
| 관점 | 운영자·조직 (재정, 법인, 데이터 관리 포함) | 직접 만드는 디자이너, 가볍게 |
| 사람 사이의 관계 | 독립된 주제 없음 (공유 경험, 역할 속에 암묵적) | **관계**를 독립된 설계 대상으로 (사용자-사용자 관계가 핵심 메시지) |
| 온·오프라인 | 채널과 플랫폼이 '구조'에만 있음 | 접점을 경험 단계마다 다룸 |
| 측정 | 성공의 정의는 묻지만 측정 방법은 없음 | 공동체 의식 + 행동 신호 |
| 수준 | 핵심 질문 | 원칙 + 핵심 질문 (같은 수준 → 우리 선택의 타당성 근거) |

## 가져올 것
1. **질문 중심 형식**: 정답 대신 질문을 주는 방식이 실무에서 쓰였다는 선례 → 원칙 + 핵심 질문 형식의 근거
2. **정체성(목적·구성원 정체성·가치)을 중심에**: 우리 설계 대상 "목적"을 "정체성과 목적"으로 넓히는 것 검토
3. **출구(전환) 단계 추가**: 우리 시간 축에 떠남·비활성·졸업이 빠져 있음 → 여정 끝에 "전환" 추가 검토
4. **최소 기능 커뮤니티**: "시작하기" 단계의 근거 (Lang의 최소 기능 커뮤니티와 같은 개념)
5. **최소 핵심 활동**: 주도·지속 단계에서 번아웃을 다루는 원칙의 근거

## 차별점 (논문에 쓸 문장 초안)
Community Canvas는 커뮤니티가 다뤄야 할 주제를 망라한 질문 목록으로, 실무에서 널리 쓰였지만 ①구성원 경험의 시간 흐름, ②단계별로 부딪히는 설계 긴장, ③사람 사이의 관계 자체, ④연구 근거와 측정을 다루지 않는다. 본 연구의 프레임워크는 이 공백을 직접 만드는 디자이너의 관점에서 보완한다. (연구자 해석)
