# 22. 기존 프레임워크 비교 ①: Community Canvas

## 서지
Pfortmüller, F., Luchsinger, N., & Mombartz, S. (2017). *The Community Canvas Guidebook* (Version 1.0, May 2017). https://community-canvas.org/ (CC BY-NC-SA 4.0)
- 읽은 범위: 가이드북 PDF 텍스트 중 서론, 세 섹션 개요, Member Selection, Member Transition, Rituals, Organization 부분 / 17개 주제와 핵심 질문은 Commons Library 요약과 가이드북으로 대조
- 프로젝트는 종료됨(사이트와 가이드북은 공개 유지). 후속 Community Canvas 2.0은 나오지 않은 것으로 보임. 후속 성격의 Community Weaving 프로젝트(Lang 강연에서 언급)는 Notion 페이지가 열리지 않아 확인 못 함

## 정의
"a community is a type of organization that brings people together and makes them feel like they belong" (p.3) — 소속감 중심 정의로 Lang, McMillan & Chavis와 같은 방향

## 구조: 3개 섹션, 17개 주제 (각 주제는 핵심 질문으로 구성)
| 섹션 | 질문 | 주제 |
|---|---|---|
| 정체성 Identity | 우리는 누구이고 무엇을 믿는가 | 목적, 구성원 정체성, 가치, 성공의 정의, 브랜드 |
| 경험 Experience | 커뮤니티에서 무슨 일이 일어나고 구성원에게 어떤 가치를 주는가 | 구성원 선발(입구), 구성원 전환(출구), 공유 경험, 의례와 전통, 콘텐츠, 규칙, 역할 |
| 구조 Structure | 장기적인 안정성은 무엇에서 오는가 | 조직, 거버넌스, 재정, 채널과 플랫폼, 데이터 관리 |
- 정체성이 시각적으로도 가운데에 있고 다른 모든 것에 영향 (p.5)
- 최소 기능 커뮤니티(Minimum Viable Community) 템플릿: 핵심 질문 9개, 정체성과 경험 섹션만 다룸. 구조 섹션은 성숙한 단계에서 중요 (UNaLAB 툴킷)

## 우리 연구와 직접 연결되는 내용
- **Member Selection**: 개방형은 포용적이지만 "더 모호"해지고, 폐쇄형은 "엘리트주의"의 인상을 줄 수 있으며 투명한 선발이 이를 일부 상쇄 (p.24) → 설계 긴장 "낮은 문턱 ↔ 의도된 마찰", "소속감 ↔ 배타성"의 실무 근거
- **온보딩**: 환영받고 안전하다는 느낌, 핵심 가치와 규칙 소개, 기대되는 헌신 명확화, 분명한 첫 몇 걸음, 그룹 안의 첫 연결 돕기. "가능한 한 개인적일수록" 잘 작동 (p.25)
- **Member Transition(출구)**: 대부분의 커뮤니티는 시작은 고민하지만 끝은 계획하지 않음. 경험에 끝을 두면 핵심 기간의 활동과 리텐션이 높아짐. 비활성 회원을 정의하고 다시 참여시키거나 내보내는 절차, 동문 커뮤니티 (p.27)
- **Rituals**: 의례는 구성원 경험의 단계(시작, 성장, 끝)를 표시하는 통과의례 (p.33) → 단계 축과 연결
- **Organization**: 열정의 주기가 식으면 자원이 줄어듦 → 성숙한 커뮤니티는 꼭 지켜야 할 "최소 핵심 활동"을 정해둠 (p.46) → 주도·지속 단계, 운영자 번아웃

## 우리 프레임워크와의 비교
| 기준 | Community Canvas | 우리 프레임워크(안) |
|---|---|---|
| 조직 방식 | **무엇을** 다루나 (주제별 분류) | **언제**(단계) × **무엇을**(설계 대상) |
| 시간 축 | 입구와 출구만 있고 중간 단계는 없음 (의례에서 단계 언급) | 시작 → 진입 → 재방문 → 정착 → 주도(→ 전환) |
| 긴장·딜레마 | 성찰 글 안에 암묵적으로 (개방 vs 폐쇄 등) | 단계마다 설계 긴장을 명시 |
| 근거 | 저자들의 15년 경험 + 실무자 의견 (학술 근거 없음) | 이론·질적 연구·설문으로 추적 가능한 근거 |
| 관점 | 운영자·조직 (재정, 법인, 데이터 관리 포함) | 직접 만드는 디자이너, 가볍게 |
| 사람 사이의 관계 | 독립된 주제 없음 (공유 경험, 역할 속에 암묵적) | **관계**를 독립된 설계 대상으로 (사용자-사용자 관계가 핵심 메시지) |
| 온·오프라인 | 채널과 플랫폼이 '구조'에만 있음 | 접점을 경험 단계마다 다룸 |
| 측정 | 성공의 정의는 묻지만 측정 방법은 없음 | 공동체 의식 + 행동 신호 |
| 수준 | 핵심 질문 | 원칙 + 핵심 질문 (같은 수준 → 우리 선택의 타당성 근거) |

## 가져올 것
1. **질문 중심 형식**: 정답 대신 질문을 주는 방식이 실무에서 쓰였다는 선례 → 원칙 + 핵심 질문 형식의 근거
2. **정체성(목적·구성원 정체성·가치)을 중심에**: 우리 설계 대상 "목적"을 "정체성과 목적"으로 넓히는 것 검토
3. **출구(전환) 단계 추가**: 우리 시간 축에 떠남·비활성·졸업이 빠져 있음 → 여정 끝에 "전환" 추가 검토
4. **최소 기능 커뮤니티**: "시작하기" 단계의 근거 (Lang의 최소 기능 커뮤니티와 같은 개념)
5. **최소 핵심 활동**: 주도·지속 단계에서 번아웃을 다루는 원칙의 근거

## 차별점 (논문에 쓸 문장 초안)
Community Canvas는 커뮤니티가 다뤄야 할 주제를 망라한 질문 목록으로, 실무에서 널리 쓰였지만 ①구성원 경험의 시간 흐름, ②단계별로 부딪히는 설계 긴장, ③사람 사이의 관계 자체, ④연구 근거와 측정을 다루지 않는다. 본 연구의 프레임워크는 이 공백을 직접 만드는 디자이너의 관점에서 보완한다. (연구자 해석)

## 라이선스 주의
CC BY-NC-SA 4.0 → 논문에서 인용·비교는 문제없음. Canvas의 구성을 변형해 우리 프레임워크에 넣는다면 출처를 밝히고, 그 부분은 같은 라이선스(비상업·동일조건)로 공개해야 함

# 기존 프레임워크 비교 ②: Community Weaving Framework

## 서지
Dixon, E., Pfortmüller, F., Bachmann, M., & Magnuson, S. (연도 미확인). *The Community Weaving Handbook*. https://communityweaving.notion.site/ (CC BY-NC-SA 4.0)
- 읽은 범위: 2026-10-26 헤드리스 브라우저로 Welcome, What is Community, The Framework, 5개 요소, Working with the Framework, About the Project 페이지 본문 확인 (자료 목록 링크의 개별 글은 읽지 않음, 이미지 일부는 로드 실패)
- 출처: Community Canvas의 다음 버전을 만들려던 작업에서 출발, 100명 이상의 커뮤니티 운영자와 대화, 원주민·선조의 지혜 등 다양한 앎의 방식을 탐구 (About)
- Lang(2025) 강연에서 언급한 "Community Weaving Project"의 캔버스, 최소 기능 커뮤니티가 이 프로젝트

## 정의
"community is a web of mutual care around a shared possibility" (공유된 가능성을 둘러싼 상호 돌봄의 그물망)
- "we can't build a web of relationships. … community is a living practice" (관계의 그물은 만들(build) 수 없고, 커뮤니티는 살아 있는 실천) → "엮다(weaving)"라는 말을 쓰는 이유

## 5개 요소
| 요소 | 질문 | 내용 |
|---|---|---|
| 불 The Fire | 무엇이 우리를 모으나 | 공유된 목적, 핵심 가치, 집단 정체성, 소속감. 처음엔 불씨, 이야기와 대화로 키움 ("What draws you to this community?") |
| 그물 The Web | 무엇이 우리를 붙잡아 두나 | 관계의 그물. 신뢰·존중·관대함·상호 돌봄일 때 강함. 서로 알게 될 의도적인 기회를 만들고, 긴장을 솔직하게 다룰 때 회복 |
| 리듬 The Rhythm | 어떻게 정기적으로 연결되나 | 모임, 의례 같은 반복되는 실천. 꾸준함이 불을 지킴. 바쁜 시기와 쉬는 시기의 순환도 포함 |
| 원 The Circles | 어떤 역할을 할 수 있나 | 안쪽 원(전체를 돌보는 사람), 가운데 원(적극 참여자), 바깥 원(느슨하게 연결된 사람). 참여 수준을 이름 붙이지 않으면 죄책감·좌절·번아웃. 원 사이를 오가는 문턱과 호혜·자원·권력에 대한 합의 |
| 나선 The Spiral | 어떻게 함께 여정을 가나 | 사람들은 들어오고, 머물고, 떠남. 전환의 순간(들어올 때의 입문 의례, 떠날 때의 감사 의례)을 기림. 집단 차원에서도 주기적으로 무엇을 지키고 바꿀지 대화 |
- 사용 원칙: "All models are wrong but some are useful." 프레임워크를 너무 진지하거나 문자 그대로 받아들이지 말 것. 요소 간 관계 탐색 권장 (예: 원마다 다른 리듬이 필요, 원이 어긋나면 그물이 찢어짐)
- 한 장짜리 Minimum Viable Canvas 제공 (이미지 로드 실패로 내용 미확인)

## 우리 연구와의 관계
- **바로잡을 점**: ①번 비교에서 "사람 사이의 관계가 독립된 주제로 없다"는 Community Canvas에만 해당. Community Weaving은 **관계(The Web)를 독립 요소로** 둠 → 우리 차별점을 "관계를 다룬다"가 아니라 아래로 수정
- **지지하는 점**
  - "관계는 만들 수 없고 엮고 가꾸는 것" → Lang의 "정원 가꾸기", 우리 C 유형(관점 전환)과 같은 방향. "제품" 비유를 조심해야 한다는 판단의 근거
  - 원(Circles) = Lang의 동심원, 우리 주도 단계와 번아웃 문제
  - 나선(Spiral) = 들어오고 떠나는 여정 → 우리 시간 축에 "전환" 단계를 넣을 근거
  - 리듬(Rhythm) = "자유 ↔ 리듬" 설계 긴장
  - 자료 목록의 "Community weaving is about creating (safe) excuses for people to connect" → 활동이 관계를 매개한다(러닝크루, 소프트 소셜라이징)와 같은 관점

## 세 프레임워크 비교
| 기준 | Community Canvas (2017) | Community Weaving | 우리 프레임워크(안) |
|---|---|---|---|
| 성격 | 주제별 질문 목록 (17개) | 관계 중심 은유 (5개 요소) | 단계 × 설계 대상 + 긴장 |
| 시간 흐름 | 입구·출구만 | 나선(흐름은 있으나 단계는 없음) | 시작 → 진입 → 재방문 → 정착 → 주도 → 전환 |
| 관계 | 독립 주제 없음 | 그물(Web)로 중심에 | 관계를 설계 대상으로 + 사용자-사용자 관계라는 메시지 |
| 설계 긴장 | 암묵적 | 요소 간 관계 탐색 권장 | 단계별로 명시 |
| 근거 | 저자 경험 + 실무자 | 실무자 100명 이상 대화 + 원주민·선조의 지혜 | 연구 문헌·질적 연구·설문으로 추적 가능 |
| 사용자 관점 | 운영자·조직 | 커뮤니티를 엮는 사람(가치 지향) | 직접 만드는 디자이너 |
| 디자인 실무와의 연결 | 없음 | 없음 | UX 과업과의 대응(A·B·C), 측정 신호 |
| 측정 | 성공의 정의만 | "Community Test" 글 소개 정도 | 공동체 의식 + 행동 신호 |

## 수정한 차별점 문장 (초안)
Community Canvas와 Community Weaving은 실무자 경험에 기반해 커뮤니티의 구성 요소를 질문과 은유로 제시했다. 후자는 관계를 커뮤니티의 중심에 두었다. 그러나 두 프레임워크 모두 ①구성원 경험의 단계별 흐름, ②단계마다 부딪히는 설계 긴장, ③디자이너가 이미 가진 방법과의 연결, ④연구 근거와 측정 신호를 체계적으로 다루지 않는다. 본 연구는 이를 직접 만드는 디자이너의 관점에서 보완한다. (연구자 해석)
